# `ModelViewer`

The primary exported component. Renders a GLB, GLTF, OBJ, FBX, or USDZ model with orbit/pan/zoom controls, built-in side panels, and a full callback API.

## Presets and grouped props

`preset` sets `ModelViewer` up for a common kind of page:

| Preset | For | What it sets |
| --- | --- | --- |
| `minimal` | Just the model | Hides both panels, the download and reset buttons, and tour controls |
| `showcase` | A product on display | Everything `minimal` does, plus auto-rotation |
| `configurator` | Customers changing parts | Shows the selected object's panel and the reset button; hides the scene objects panel and download |
| `inspector` | Checking a model | Every panel, the view gizmo, the measure, UV checker, and exploded-view tools, and keyboard navigation |

`MODEL_VIEWER_PRESETS` lists exactly which props each preset sets.

Related props are also available as groups, which keeps a configured viewer
readable:

```tsx
<ModelViewer
  modelUrl="/car.glb"
  licenseKey="your-license-key"
  preset="configurator"
  ui={{ download: "car.glb" }}
  tools={{ measure: { unit: "cm" } }}
  controls={{ autoRotate: 0.5, zoom: false, limits: { maxDistance: 20 } }}
  perf={{ profile: "low" }}
  xr={{ enabled: true, usdzUrl: "/car.usdz" }}
/>
```

| Group | Fields, and the flat prop each one sets |
| --- | --- |
| `ui` | `objectPanel` (`showObjectBindingDataPanel`), `sceneObjects` (`showSceneObjectsPanel`), `download` (`showDownloadButton`; a string also sets `downloadFilename`), `reset` (`showResetButton`), `loadingOverlay` (`showLoadingOverlay`), `viewGizmo` (`showViewGizmo`), `mouseController` (`showMouseController`; `{ position, opacity }` also sets `mouseControllerPosition` and `mouseControllerOpacity`), `annotationNavigation` (`showAnnotationNavigation`), `annotationOnHover` (`showAnnotationOnHover`), `highlightOnHover` |
| `tools` | `measure` (`showMeasureTools`; `{ unit }` also sets `measurementUnit`), `uvChecker` (`showUvCheckerButton`), `explode` (`showExplodeControls`), `texturePositioning` (`texturePositioning`) |
| `controls` | `enabled` (`enableCameraControls`), `keyboard` (`enableKeyboardNavigation`), `zoom` (the opposite of `disableZoom`), `zoomOnSelect` (`zoomOnSelected`), `autoRotate` (a number also sets `autoRotateSpeed`), `refitOnResize`, `limits` (`cameraLimits`), `moveSensitivity`, `zoomSensitivity` |
| `perf` | `renderMode`, `maxDpr`, `profile` (`performanceProfile`), `preserveDrawingBuffer` |
| `tiles` | `url` (`tilesetUrl`), `errorTarget` (`tilesErrorTarget`), `cacheSize` (`tilesCacheSize`) |
| `xr` | `enabled` (`enableXR`), `usdzUrl`, `scaleMode` (`arScaleMode`), `mobileHandoffUrl` |
| `decoders` | `draco` (`dracoDecoderPath`), `ktx2` (`ktx2TranscoderPath`), `meshopt` |

A preset only fills in defaults: a flat prop overrides it, and a grouped prop
overrides both. The flat props keep working exactly as before.

### `modelUrl`

**Required.** URL or public path to a `.glb`, `.gltf`, `.obj`, `.fbx`, or `.usdz` model. Hosted assets must serve external buffers, MTL files, and textures at their declared relative paths; USDZ dependencies are packaged internally.

```tsx
<ModelViewer modelUrl="/model.glb" ... />
```

---

### `modelFormat`

Optional explicit format for extensionless or signed URLs. Supported file extensions are detected automatically in normal URLs.

```tsx
<ModelViewer modelUrl={signedUrl} modelFormat="fbx" ... />
```

This is separate from `usdzUrl`: `modelUrl` renders USDZ inside the viewer,
while `usdzUrl` launches the native Apple Quick Look experience when XR is
enabled.

---

### 3D Tiles streaming

Use `tilesetUrl` to stream a processed 3D Tiles model instead of downloading
`modelUrl` as one monolithic asset. `modelUrl` remains required by the component
API, but `tilesetUrl` is the render source while streaming is enabled.

```tsx
<ModelViewer
  modelUrl="/models/campus.glb"
  tilesetUrl="/models/campus/tileset.json"
  tilesErrorTarget={8}
  tilesCacheSize={800}
  onObjectCatalog={(objects) => console.log(objects)}
  {...props}
/>
```

- `tilesErrorTarget` controls the screen-space error target. Lower values load
  sharper tiles and use more bandwidth/GPU memory. Default: `8`.
- `tilesCacheSize` is the maximum number of parsed tiles kept in the client
  cache. Default: `800`.
- `onObjectCatalog` receives the bindable-object catalog from `objects.json`
  before all referenced tiles have loaded. See [`onObjectCatalog`](#onobjectcatalog).

Bindings, selection, hover, material overrides, transforms, exploded view, and
scene renderer modes use the same public API in streamed and monolithic modes.
The tileset and its tile payloads must be browser-accessible, and the optional
object catalog must sit beside `tileset.json` as `objects.json`.

### `licenseKey`

**Required.** License key for the library.

```tsx
<ModelViewer licenseKey="your-license-key" ... />
```

To get a license key, sign in at the [React Immersive Console](https://react-immersive.liveroom.dev/console), choose a plan, and generate a key from your dashboard.

The browser validates the key against
`https://react-immersive.liveroom.dev/api/validate-license`. A successful
result is cached in memory for five minutes and may include a signed,
domain-and-key-scoped offline grant valid for up to 12 hours. If validation is
temporarily indeterminate, an unexpired signed grant is used immediately when
available. Without one, the SDK retries once after a 400 ms backoff; each
attempt has a five-second timeout. Timeouts, transport failures, `429`, `5xx`,
and malformed responses are retryable, while explicit licence denials are not.
A first-time visitor without a valid grant fails closed if both attempts fail.

### `objectBindings`

A map keyed by the model node identifier, or `"auto"`, the default (see
[Generating bindings automatically](#generating-bindings-automatically)). A uniquely named mesh
keeps its authored name. When a model contains duplicate node names, each
duplicate receives a stable traversal-order identifier such as `Cube [1]` and
`Cube [2]`; the original `Object3D.name` is not mutated, so animation tracks
continue to work. `BindingBuilder` generates these identifiers automatically
and the viewer logs the duplicate-name mapping to the console.

`objectBindings` is the single source of truth for all visual state:

| Field                                         | Effect                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| `visible`                                     | Controls mesh visibility                                                      |
| `style.material.baseColor`                    | Sets mesh color (committed by the built-in color picker on close)             |
| `style.material.texture.path`                 | Sets the base color (albedo) texture                                          |
| `style.material.*`                            | Per-object `MeshPhysicalMaterial` overrides, see below                       |
| `cameraState.position` / `cameraState.target` | Camera view to use when this object is focused or selected from the viewer UI |

All visual overrides live under `style.material` (an `ObjectBindingMaterial`).
It covers base color/PBR, emission, opacity & blending, normal/bump,
displacement, ambient occlusion, clearcoat, sheen, anisotropy,
transmission/volume, and face sidedness, plus a texture-map slot for each.
See [`ObjectBindingMaterial`](/reference/types#objectbindingmaterial) for the
full field list and the per-slot color-space handling (color maps are decoded
as sRGB, data maps stay linear).

#### Generating bindings automatically

`objectBindings` defaults to `"auto"`: leave it out and the viewer generates a
binding for every mesh when the model loads:

```tsx
<ModelViewer modelUrl="/model.glb" licenseKey={licenseKey} />
```

Each generated binding is keyed by the node identifier, with a readable
`label`, an inferred `type`, a unique `id`, and built-in actions
(`change-color`, `change-material`, `toggle-visibility`, or the three light
actions for meshes whose names contain "light"). For a streamed model
(`tilesetUrl`), bindings come from the object catalog.

The generated bindings are reported through `onObjectBindingsChange`. To keep
and refine them, store them and pass them back. After the first change the
viewer is controlled by your state; set it back to `"auto"` when you switch
models:

```tsx
const [objectBindings, setObjectBindings] = useState<
  Record<string, ObjectBinding> | "auto"
>("auto");

<ModelViewer
  modelUrl={modelUrl}
  licenseKey={licenseKey}
  objectBindings={objectBindings}
  onObjectBindingsChange={setObjectBindings}
/>;
```

While the prop is `"auto"`, a reload of the same model keeps the bindings it
already had, so runtime edits survive; a different `modelUrl` starts fresh.
`buildBindingsFromNodes`, `createDefaultBinding`, and `inferType` are exported
from `@liveroom-tech/react-immersive/utils` for building the same defaults
yourself. They're the same defaults `BindingBuilder` generates.

```ts
const objectBindings = {
  Object_2: {
    id: "obj-2",
    modelObjectId: "Object_2",
    type: "body",
    visible: true,
    cameraState: {
      position: [2.8, 1.6, 4.2],
      target: [0, 0.8, 0],
    },
    style: {
      material: {
        baseColor: "#ff0000",
        texture: { path: "/materials/body-finish.jpg" },
        roughness: 0.4,
        clearcoat: 1,
      },
    },
    actions: [
      { id: "change-color", label: "Change Color", type: "command" },
      { id: "toggle-visibility", label: "Toggle Visibility", type: "command" },
    ],
    metrics: {},
    metadata: {},
  },
};
```

### `selectedObject`

Optional currently selected object binding, or `null` when nothing is selected.

When provided, `ModelViewer` behaves as a **controlled component**. When omitted, it manages its own selection state internally.

When the selected object has a `cameraState` with both `position` and `target`, the viewer uses that saved camera view for focus/select behavior instead of falling back to `fitToBox`.

---

### `panelHoveredObject`

Optional externally controlled binding to highlight as hovered by a custom
scene-objects panel. It takes precedence over the built-in panel and canvas
hover while `highlightOnHover` is enabled. Pass `null` when no panel row is
hovered.

---

### `onObjectSelect`

Called when the user clicks a mesh or closes the side panel.

```ts
onObjectSelect?: (binding: ObjectBinding | null) => void
```

- Clicking a mesh → `onObjectSelect(binding)`
- Closing the panel → `onObjectSelect(null)`
- Clicking the same mesh again still fires; selection is not toggled off automatically
- If the binding includes `cameraState.position` and `cameraState.target`, the viewer moves the camera to that saved view when focusing that object
- Clicks resolve the front-most surface under the pointer; a mesh whose binding has `selectable: false` does not pass the click through to meshes behind it
- On very large models, clicking meshes in the viewport is disabled entirely, see [Large models](#large-models). Selection through the scene objects panel (and this callback) still works

---

### `onObjectHover`

Called when the user hovers a mesh.

```ts
onObjectHover?: (binding: ObjectBinding | null) => void
```

- Pointer over a mesh → `onObjectHover(binding)`
- Pointer out → `onObjectHover(null)`
- On very large models, viewport hover is disabled entirely, see [Large models](#large-models)

---

### `onObjectDoubleClick`

Optional callback called when the user double-clicks an object.

```ts
onObjectDoubleClick?: (event: ObjectPointerEvent) => boolean | void

type ObjectPointerEvent = {
  binding: ObjectBinding;
  clientX: number; // viewport coordinates
  clientY: number;
  pointerType: string; // "mouse" | "pen" | "touch"
};
```

Return `true` to say you handled it: the viewer then skips its own double-click
behavior, which moves the camera's orbit point to that spot (or starts texture
positioning, when `texturePositioning` is on). Return nothing to keep it.

---

### `onObjectContextMenu`

Optional callback called when the user right-clicks an object, or long-presses
it on a touch screen. Use it to open your own menu:

```tsx
<ModelViewer
  {...props}
  onObjectContextMenu={({ binding, clientX, clientY }) =>
    openMenu({ for: binding.id, x: clientX, y: clientY })
  }
/>
```

It receives the same `ObjectPointerEvent` as `onObjectDoubleClick`, with the
position where the gesture started, ready for a `position: fixed` menu. A
right-click fires when the button is released without the pointer moving, so a
right-drag still pans the camera. A long-press fires after half a second, and
not if the finger moves or a second finger touches down (a pinch); lifting the
finger afterwards doesn't select the object. Objects with `selectable: false`
don't fire it.

---

### `onObjectBindingsChange`

Fired when the viewer's built-in UI updates binding data. Wire this back into your state to keep the viewer and your app in sync.

```ts
onObjectBindingsChange?: (next: Record<string, ObjectBinding>) => void
```

Fires for:

- Visibility toggles (`binding.visible`)
- Color picks (`binding.style.material.baseColor`), committed when the color picker closes
- Texture uploads (`binding.style.material.texture.path`)
- Texture removal
- Object movement and rotation (`binding.transform.position` and `binding.transform.rotation`)

Passing this callback makes binding edits controlled: update the
`objectBindings` prop with the returned record. If it is omitted, the viewer
keeps built-in edits in internal state for the lifetime of the mounted viewer.

```ts
onHiddenObjectsChange?: (next: Record<string, boolean>) => void
```

### `onObjectCatalog`

Lists every bindable object in the model: each named mesh, under the identifier
`objectBindings` is keyed by. It's the quickest way to find out what your meshes
are called:

```tsx
<ModelViewer
  modelUrl="/model.glb"
  licenseKey={licenseKey}
  onObjectCatalog={(objects) => console.table(objects)}
/>
```

It fires each time a model loads. For a streamed model (`tilesetUrl`), the list
comes from `objects.json`, before the tiles containing those objects have
necessarily loaded. Each entry is a
[`ViewerObjectInfo`](/reference/types#viewerobjectinfo). To keep the list in
state, pass [`useViewerModel`](/hooks/use-viewer-model)'s
`handleObjectCatalog`.

### `onModelLoaded`

Called after the model has loaded, with its bounds and mesh count.

```ts
onModelLoaded?: (model: ViewerModelInfo) => void

type ViewerModelInfo = {
  bounds: { min: Vec3; max: Vec3; center: Vec3; size: Vec3 }; // world space
  objectCount: number; // meshes in the loaded scene
};
```

For the model's object names, use [`onObjectCatalog`](#onobjectcatalog).

### `onLoadError`

Called if the model fails to load or render.

```ts
onLoadError?: (error: unknown) => void
```

Whether or not you pass it, `ModelViewer` shows a message in place of the model
that explains the likely cause: a missing file (404), refused access (401/403),
a blocked cross-origin request (CORS), a web page served instead of a model, or
a file that isn't the expected format. It includes the URL and the underlying
error. Set `showLoadingOverlay={false}` to show your own instead.

---

### `onProgress`

Called with the loader's `ProgressEvent` while a monolithic model is being
downloaded. When `event.lengthComputable` is true, progress is
`event.loaded / event.total`; the built-in loading overlay uses the same value.

```ts
onProgress?: (event: ProgressEvent) => void
```

### `onAction`

Called when a built-in action button is clicked from the side panel.

```ts
type ObjectActionEvent = {
  objectId: string;
  action: ObjectBindingAction;
  binding?: ObjectBinding;
  screenX?: number;
  screenY?: number;
};

onAction?: (event: ObjectActionEvent) => void
```

`ModelViewer` performs `change-color`, `change-material`, `toggle-visibility`,
`toggle-light`, `change-light-color`, and `set-brightness` itself. The light
actions turn the object's light on and off, open a color picker, and open a
0–200% brightness slider. If scene lights are attached to the object they
control those, updating `sceneConfig.lighting` (through `onSceneConfigChange` if
you pass it, otherwise inside the viewer); otherwise they control the object's
own glow, saved on its binding as `style.material.emissive` and
`emissiveIntensity`. Any other action id does something only when
you handle it here (pass `useViewerActions().handleAction` to run an action's
declared `effects`). Without `onAction`, those buttons do nothing, and the
viewer logs a console warning naming each one. `ACTION_CATALOG` and
`findCatalogAction`, from `@liveroom-tech/react-immersive/utils`, list the ids
`BindingBuilder` offers and whether the viewer or your app handles each one.

### `onViewerReady`

Called once camera controls are available and again when the viewer publishes updated ready-state data (for example after model load, camera changes, or binding changes).

```ts
onViewerReady?: (viewer: ViewerReadyState) => void

type ViewerReadyState = {
  objectBindings: Record<string, ObjectBinding>;
  homeCameraState: { position: Vec3; target: Vec3 } | null;
  captureImage: (options?: CaptureImageOptions) => Promise<string>;
  invalidate: () => void;
  raw: {
    controls: CameraControls; // camera-controls
    scene: Object3D | null; // three.js
    nodes: Record<string, Object3D>; // model nodes by binding key and name
  };
};

type CaptureImageOptions = {
  width?: number;
  height?: number;
  transparent?: boolean;
};
```

`raw` holds the live three.js scene, the camera-controls instance, and the
model's nodes, for integrations the rest of the API doesn't cover. You don't
need it for anything the hooks and props already do, and its shapes are those
libraries' own, so they can change when those libraries do.

`captureImage` requires the opt-in `preserveDrawingBuffer` prop, forces a render, and resolves with a `data:image/png` URL of the canvas. Pass `width`/`height` to render at a resolution other than the canvas's current size, and `transparent` to hide the configured background so the PNG has an alpha channel. It rejects if called before the viewer is ready or when framebuffer preservation is disabled.

```tsx
<ModelViewer
  preserveDrawingBuffer
  onViewerReady={(viewer) => {
    viewer
      .captureImage({ width: 1920, height: 1080, transparent: true })
      .then((dataUrl) => {
        // upload, preview, etc.
      });
  }}
/>;
```

For turning the current camera/visibility/selection into a shareable link, see [`useShareableViewerState`](/hooks/use-shareable-viewer-state).

### `onTextureUpload`

Optional async callback for handling texture file uploads. Use it to upload to your own storage (S3, Cloudinary, CDN, etc.) and return a durable URL.

```ts
onTextureUpload?: (file: File, objectId: string) => Promise<string>
```

When omitted, the viewer falls back to `URL.createObjectURL(file)`, a session-scoped blob URL that is lost on reload.

```tsx
<ModelViewer
  onTextureUpload={async (file, objectId) => {
    const formData = new FormData();
    formData.append("file", file);
    formData.append("objectId", objectId);
    const res = await fetch("/api/upload-texture", {
      method: "POST",
      body: formData,
    });
    const { url } = await res.json();
    return url;
  }}
/>
```

### `texturePositioning`

Turns on texture positioning for objects with an uploaded texture. Off by
default. When on, the **Change Material** panel gains Offset X/Y and Rotation
controls, and double-clicking the object puts the viewer in Move/Zoom mode:
drag to move the texture, scroll to scale it, and click the canvas or
**Done positioning** to finish.

```tsx
<ModelViewer modelUrl="/sofa.glb" licenseKey="your-license-key" texturePositioning />
```

Changes are written to the binding's `style.material.texture` (`offset`,
`rotation` in radians, and `scale`), so they reach `onObjectBindingsChange`
and your saved bindings like any other edit.

To handle some of it yourself, pass an object instead of `true`. Any field you
leave out keeps the viewer's own behavior:

```ts
type TexturePositioningControls = {
  offset?: [number, number]; // shown in the Offset fields instead of the binding's
  rotationDegrees?: number; // shown in the Rotation field, 0–360
  onOffsetChange?: (objectId: string, axisIndex: 0 | 1, value: number) => void;
  onRotationChange?: (objectId: string, degrees: number) => void;
  isPositioning?: boolean; // shows "Done positioning" instead of the hint
  onEndPositioning?: () => void; // after Done positioning ends the mode
};
```

`onOffsetChange` and `onRotationChange` replace the viewer's writes from the
panel fields; dragging and scrolling on the canvas still write to the binding.

### `onAnimationsReady`

Called after the model is loaded, providing animation controls for supported
embedded GLB/GLTF, FBX, or USDZ animations. Called even if the model has no
animations (empty `clips` array, no-op functions).

```ts
type AnimationControls = {
  clips: string[];
  clipDetails?: { sourceName: string; duration: number }[];
  play: (clipName: string) => void;
  pause: () => void;
  stop: () => void;
  setSpeed: (speed: number) => void;
  seek?: (time: number) => void; // scrub the current clip to an absolute time (seconds)
  getState?: () => AnimationPlaybackState; // includes live time + duration
  subscribe?: (listener: (state: AnimationPlaybackState) => void) => () => void;
};

onAnimationsReady?: (controls: AnimationControls) => void
```

See [`AnimationControls`](/reference/types#animationcontrols) for the full
`AnimationPlaybackState` shape (`currentClip`, `isPlaying`, `speed`, `time`,
`duration`).

Wire to `useViewerAnimations().handleAnimationsReady` for the simplest integration.

### Lighting

Lighting lives in `sceneConfig.lighting`: an ambient light plus a list of
directional, point, spot, and hemisphere lights. Without a `sceneConfig`,
`ModelViewer` uses its default rig (ambient, a hemisphere fill, and a
shadow-casting key light). To use your own lights, patch the default scene
config. `sceneLight` fills in every setting you leave out:

```tsx
import {
  DEFAULT_SCENE_CONFIG,
  patchSceneConfig,
  sceneLight,
} from "@liveroom-tech/react-immersive/utils";

const sceneConfig = patchSceneConfig(DEFAULT_SCENE_CONFIG, {
  lighting: {
    ambient: { intensity: 0.5 },
    lights: [
      sceneLight({ id: "key", type: "directional", position: [4, 8, 4], intensity: 1.6, castShadow: true }),
      sceneLight({ id: "fill", type: "point", position: [-3, 3, 2], intensity: 0.8 }),
    ],
  },
});

<ModelViewer
  modelUrl="/model.glb"
  licenseKey="your-license-key"
  sceneConfig={sceneConfig}
/>;
```

To change lights while the app runs, use the lights controller from
`useViewer` (or `useSceneConfig`):

```tsx
const viewer = useViewer({ sceneConfig });

viewer.scene.lights.setIntensity("key", 2.2);
viewer.scene.lights.toggle("fill");
viewer.scene.lights.add({ id: "bulb", type: "point", color: "#ffd27d", intensity: 4 });
viewer.scene.lights.attach("bulb", { objectId: "Lamp", offset: [0, 1.4, 0] });
```

An attached light follows the object, offset from the object's origin in its
local space (the origin is often at its base, not its center). Lighting set up
in `BindingBuilder`'s Scene tab exports as the same `sceneConfig`.

### `shadows`

Controls whether the viewer renders shadows. Default: `true`.

When `true`, the canvas renders soft shadows: the default light rig casts a directional key-light shadow, furniture/decor meshes cast and receive shadows, and ambient occlusion is applied via post-processing. When `false`, shadow-map rendering is disabled on the canvas, no shadow-pass cost, and per-mesh/light `castShadow` flags are ignored.

```tsx
<ModelViewer shadows={false} ... />
```

<Callout type="info">
  **Interior models (rooms, dollhouses):** the large mesh that forms the
  walls/ceiling enclosure is detected by its bounding-box size and automatically
  excluded from **casting** shadows (it still **receives** them). Without this,
  a closed shell would block a top-down light and seal the interior in darkness.
  Furniture and decor then cast realistic contact shadows onto the floor. Pass a
  your own lights in `sceneConfig.lighting` (see [Lighting](#lighting)) to replace
  the default rig.
</Callout>

### `cameraLimits`

Constrains how far the orbit camera can zoom, tilt, turn, and pan. Angles are
in degrees.

```tsx
<ModelViewer

  cameraLimits={{

    maxDistance: 12,

  }}
```

```ts
type CameraLimits = {
  minDistance?: number; // default 0
  maxDistance?: number; // default Infinity
  minPolarAngle?: number; // degrees, default 0
  maxPolarAngle?: number; // degrees, default 180
  minAzimuthAngle?: number; // degrees, default -Infinity
  maxAzimuthAngle?: number; // degrees, default Infinity

```

`panBoundary` is an axis-aligned world-space box. These limits apply to the
orbit controller; pointer-lock mode is not orbiting around the same target.

### `sceneConfig`

Optional scene-wide configuration object, model, camera, lighting, wireframe,

```tsx
const { sceneConfig, updateSceneConfig } = useSceneConfig(initialSceneConfig);
```

### Moving and rotating objects

Set `moveModeEnabled` to show a centered `PivotControls` gizmo for the selected
bound object. Its translation arrows, plane handles, and rotation rings are
available at the same time; scaling is disabled.

```tsx
import { useState } from "react";
import {
  ModelViewer,
  type ObjectBinding,
} from "@liveroom-tech/react-immersive";

export function EditableViewer({
  initialBindings,
}: {
  initialBindings: Record<string, ObjectBinding>;
}) {
  const [bindings, setBindings] = useState(initialBindings);

  return (
    <ModelViewer
      modelUrl="/model.glb"
      licenseKey="your-license-key"
      objectBindings={bindings}
      onObjectBindingsChange={setBindings}
      moveModeEnabled
      objectTransformSpace="world"
    />
  );
}
```

Click a bound mesh to select it. Drag an arrow to move on one axis, a plane
handle to move on two axes, or a ring to rotate. The pivot is calculated from
the center of the object's renderable geometry, so the object rotates around
itself even when its authored node origin is elsewhere.

`objectTransformSpace` accepts:

- `"world"` (default): handles stay aligned with the scene axes
- `"local"`: handles follow the selected object's current orientation

Changing axis space only changes handle alignment; it does not move the
object. Changes are persisted to the binding as local-space
`transform.position` and `transform.rotation`. Positions use model units and
rotations use radians.

<Callout type="info">
  If you pass `selectedObject`, selection is controlled too. Update it from
  `onObjectSelect`. If you omit both props, `ModelViewer` manages selection
  internally.
</Callout>

### `dracoDecoderPath` / `ktx2TranscoderPath` / `meshopt`

Control the compressed-asset decoders used when loading the GLB/GLTF asset.

```ts
dracoDecoderPath?: string | false;
ktx2TranscoderPath?: string | false;
meshopt?: boolean;
```

Meshopt is bundled and enabled by default. DRACO and KTX2 are also enabled by
default through immutable, versioned builds hosted on the first-party
`assets.react-immersive.liveroom.dev` domain. They are fetched lazily only when a model
uses the corresponding compression format.

```ts
dracoDecoderPath =
  "https://assets.react-immersive.liveroom.dev/three-r184/draco/";
ktx2TranscoderPath =
  "https://assets.react-immersive.liveroom.dev/three-r184/basis/";
```

Copy them into your app's public/static directory:

```sh
cp -R node_modules/@liveroom-tech/react-immersive/dist/decoders public/react-immersive-decoders
```

Then pass the public URL directories, including the trailing slash:

```tsx
<ModelViewer
  dracoDecoderPath="/react-immersive-decoders/draco/"
  ktx2TranscoderPath="/react-immersive-decoders/basis/"
  {...props}

```

using the built-in defaults with a strict CSP, allow both the licence-validation

`connect-src 'self' https://react-immersive.liveroom.dev https://assets.react-immersive.liveroom.dev; worker-src 'self' blob:; script-src 'self' 'wasm-unsafe-eval'`.
Self-hosting the decoder assets removes the asset-domain requirement, but
`ModelViewer` and `BindingBuilder` still require the licence-validation origin.

### `cinematic`

Enables the cinematic auto-camera: the camera glides along a path on its own,
like a film, ideal for showing off a gallery, apartment, or product with no user
interaction. Renders a play/pause button over the canvas; grabbing the camera (or
selecting a part) pauses it and hands control back.

```ts
cinematic?: boolean | CinematicConfig;

type CinematicConfig = {
  waypoints?: CinematicWaypoint[]; // camera keyframes to glide through
  duration?: number; // seconds for one full pass (auto-scales when omitted)
  loop?: boolean; // default true
  autoPlay?: boolean; // start once the model has loaded and framed (default false)
};

type CinematicWaypoint = {
  position: [number, number, number];
  target: [number, number, number]; // world-space look-at point
  azimuthAngle?: number; // radians, captured by BindingBuilder; omit by hand
  polarAngle?: number; // radians
};
```

- Pass `cinematic` as boolean `true` (or an object with fewer than two
  waypoints) to get a zero-config **showcase orbit** around the model's bounding
  sphere.
- Pass two or more `waypoints` to author a **walkthrough**: the camera follows a
  smooth Catmull-Rom spline through them at a constant on-screen speed, looping
  seamlessly.
- Waypoints are easiest to capture visually in `BindingBuilder`'s **Cinematic**
  tab (frame a view, click _Add waypoint_), which stores them on
  `sceneConfig.cinematic`.

**Precedence.** A path can also come from
[`sceneConfig.cinematic`](#sceneconfig) (authored in BindingBuilder). The
`cinematic` prop _overwrites_ it: a boolean toggles the feature (`true` keeps any
authored waypoints, `false` forces it off), and an object overrides
field-by-field, so you can keep the authored waypoints while overriding, say,
`autoPlay` or `loop`.

```tsx
// Zero-config showcase orbit
<ModelViewer cinematic ... />

// Authored walkthrough
<ModelViewer
  cinematic={{
    waypoints: [
      { position: [4, 2, 6], target: [0, 1, 0] },
      { position: [-3, 2, 4], target: [0, 1, 0] },
      { position: [-5, 2, -2], target: [0, 1, 0] },
    ],
    loop: true,
    autoPlay: true,
  }}
  ...
/>

// Keep the BindingBuilder-authored path, just autoplay it
<ModelViewer sceneConfig={sceneConfig} cinematic={{ autoPlay: true }} ... />
```

Default: disabled.

## Large models

The viewer accelerates viewport picking by building a BVH (bounding volume
hierarchy) index for the loaded model in a background worker. Models above
roughly **12 million triangles** are too large to index without a significant
memory cost, so the viewer degrades gracefully instead:

- Viewport pointer interaction is disabled: clicking or hovering meshes in the
  canvas does nothing, and `onObjectSelect` / `onObjectHover` do not fire from
  the viewport. Selection through the scene objects panel still works and still
  fires `onObjectSelect`.
- A dismissible banner appears over the canvas telling the user the model is
  very large, that it may render slowly on their device, and that selection is
  available through the panel.
- The loading overlay narrates the extra work ("Preparing large model…"),
  uploading that much geometry to the GPU is a single synchronous operation
  that can block the page for tens of seconds, on any WebGL viewer.

Orbit, zoom, pan, animations, annotations, and the panels all keep working.

There is no way to make a model of this size feel fast in a browser, the
per-frame cost of tens of millions of triangles is inherent, and on mobile
devices the decoded geometry alone can exceed the tab's memory budget. For
assets like this, decimate at ingestion (for example to ~2–3M triangles) rather
than shipping the raw export; a decimated model loads in seconds and keeps full
interactivity. Note that Blender or native tooling is required for very large
Draco-compressed files, the WASM builds of `gltf-transform` and `gltfpack`
cannot decode them within their 4GB address space.

## Theming

The scene objects panel and object binding data panel read their colors,
borders, shadows, and fonts from CSS custom properties instead of hardcoded
values. Set them on a `.ri-viewer` ancestor (or any element wrapping the
viewer) to re-skin those panels without overriding individual classes,
every variable already has the current default baked in as a fallback, so
you only need to set the ones you actually want to change.

```css
.my-app .ri-viewer {
  --ri-sidepanel-bg: #1a0033;
  --ri-sidepanel-accent: #ff2d75;
  --ri-sidepanel-accent-soft: rgba(255, 45, 117, 0.25);
  --ri-sidepanel-text: #ffe8f5;
}
```

```tsx
<div className="my-app">
  <ModelViewer ... />
</div>
```

## Built-In Actions

| Action ID           | Behavior                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| `toggle-visibility` | Hides or shows the selected mesh via `binding.visible` + `onObjectBindingsChange`                            |
| `change-color`      | Opens the color picker inline under the action; hex committed to `binding.style.material.baseColor` on close |
| `change-material`   | Opens the texture upload panel inline under the action; URL stored in `binding.style.material.texture.path`  |
