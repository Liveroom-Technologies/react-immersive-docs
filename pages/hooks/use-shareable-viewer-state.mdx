# `useShareableViewerState`

Save and restore a complete viewer configuration as JSON, an inline URL, or an
application-owned short link. Existing camera/visibility/selection links remain
readable. Complete snapshots include binding materials, textures, decals,
transforms (including pivots/shear), actions and metadata. Pass `configuration`
to also include model sources, scene settings, variant choices, section cuts,
isolation, multi-selection, annotation filters and the active annotation.

## Complete configuration example

Keep the props you want to save controlled. The hook cannot inspect changes
kept privately inside a viewer. This example connects scene settings, isolation,
annotations, bindings, selection, and camera, and offers JSON download/import.

```tsx filename="configuration-sharing.tsx"
"use client";

import { useState } from "react";
import {
  DEFAULT_SCENE_CONFIG,
  MAX_VIEWER_STATE_BYTES,
  ModelViewer,
  serializeViewerState,
  useShareableViewerState,
  useViewerCamera,
  useViewerSelection,
  type ViewerConfiguration,
} from "@liveroom-tech/react-immersive";
import type { ObjectBinding } from "@liveroom-tech/react-immersive";

export function ConfigurationViewer({
  licenseKey,
  modelUrl,
}: {
  licenseKey: string;
  modelUrl: string;
}) {
  const [configuration, setConfiguration] = useState<ViewerConfiguration>({
    modelUrl,
    sceneConfig: DEFAULT_SCENE_CONFIG,
    isolation: null,
    activeAnnotation: null,
    annotationCategories: null,
  });
  const [bindings, setBindings] = useState<Record<string, ObjectBinding>>();
  const [isReady, setIsReady] = useState(false);
  const [error, setError] = useState("");
  const camera = useViewerCamera();
  const selection = useViewerSelection();
  const report = (error: unknown) => setError(String(error));
  const sharing = useShareableViewerState({
    cameraState: camera.cameraState,
    setCameraState: camera.setCameraState,
    objectBindings: bindings ?? {},
    onObjectBindingsChange: setBindings,
    selectedObjectBinding: selection.selectedObjectBinding,
    setSelectedObjectBinding: selection.setSelectedObjectBinding,
    configuration,
    onConfigurationChange: (next) => {
      if (next.modelUrl !== configuration.modelUrl) setIsReady(false);
      setConfiguration(next);
    },
    isReady,
    autoSync: false,
    onError: report,
  });

  function saveJson() {
    try {
      const blob = new Blob([serializeViewerState(sharing.getState())], {
        type: "application/json",
      });
      const url = URL.createObjectURL(blob);
      const anchor = document.createElement("a");
      anchor.href = url;
      anchor.download = "viewer-configuration.json";
      anchor.click();
      setTimeout(() => URL.revokeObjectURL(url), 0);
    } catch (error) {
      report(error);
    }
  }

  return (
    <>
      <button
        disabled={!isReady}
        onClick={() => {
          void sharing
            .createShareUrl()
            .then((url) => navigator.clipboard.writeText(url))
            .catch(report);
        }}
      >
        Copy configuration link
      </button>
      <button disabled={!isReady} onClick={saveJson}>
        Save JSON
      </button>
      <label>
        Load JSON{" "}
        <input
          type="file"
          accept=".json,application/json"
          onChange={(event) => {
            const file = event.target.files?.[0];
            event.target.value = "";
            if (!file) return;
            if (file.size > MAX_VIEWER_STATE_BYTES) {
              report("Configuration exceeds 5 MiB.");
              return;
            }
            void file.text().then(sharing.restoreState).catch(report);
          }}
        />
      </label>
      {error && <p role="alert">{error}</p>}
      <div style={{ height: 600 }}>
        <ModelViewer
          {...configuration}
          licenseKey={licenseKey}
          objectBindings={bindings ?? "auto"}
          onObjectBindingsChange={setBindings}
          selectedObject={selection.selectedObjectBinding}
          onObjectSelect={selection.handleObjectSelect}
          onCameraChange={camera.handleCameraChange}
          onSceneConfigChange={(sceneConfig) =>
            setConfiguration((old) => ({ ...old, sceneConfig }))
          }
          onIsolationChange={(isolation) =>
            setConfiguration((old) => ({ ...old, isolation }))
          }
          onActiveAnnotationChange={(activeAnnotation) =>
            setConfiguration((old) => ({ ...old, activeAnnotation }))
          }
          onAnnotationCategoriesChange={(annotationCategories) =>
            setConfiguration((old) => ({ ...old, annotationCategories }))
          }
          onModelLoaded={() => setIsReady(true)}
          onViewerReady={(ready) => {
            camera.handleViewerReady(ready);
            void sharing.restoreFromUrl().catch(report);
          }}
          refitOnResize={false}
          tools={{ section: true, isolate: true }}
        />
      </div>
    </>
  );
}
```

`getState()` returns a detached snapshot. You can store
`serializeViewerState(sharing.getState())` in a file or your own persistence
layer and restore its JSON with `restoreState(json)`. `parseViewerState(input)`
is also exported for standalone validation. These utilities are available from
the main entry and `/utils`.

## Multiple models

Include the current `modelUrl`, `models`, `mergeModels`, and active `sceneConfig`
in `configuration`. Each model entry includes its own bindings, scene settings
and merge-source prefixes. Write binding changes back to the active entry, as
shown in [multiple-model usage](https://react-immersive.liveroom.dev/docs/reference/model-viewer#multiple-models).
Apply `onConfigurationChange` to the same state that supplies these props; this
callback replaces the configuration rather than patching it. Keep `isReady`
false while a restored active model or its sources load. Staged restoration
resumes when readiness/configuration changes or `restoreFromUrl()` is called
again from `onViewerReady`. The saved camera is applied after configuration.

The configuration type also supports `modelFormat`, `tilesetUrl`,
`backgroundColor`, `shadows`, `cinematic`, `cameraControllerType`,
`objectTransformSpace`, `arScaleMode`, and `usdzUrl`. License keys, callbacks,
React overlays, raw Three.js objects, transient animation playback positions,
and measurement picks are not serialized. The active annotation identifies the
current tour stop; it does not start or resume tour autoplay.

## Short links with application-owned storage

For large configurations, provide a `ViewerStateStorage` adapter:

```ts
import type {
  ShareableViewerState,
  ViewerStateStorage,
} from "@liveroom-tech/react-immersive";

const storage: ViewerStateStorage = {
  async save(state: ShareableViewerState) {
    const response = await fetch("/api/configurations", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify(state),
    });
    if (!response.ok) throw new Error("Could not save configuration");
    const result: { id: string } = await response.json();
    return result.id;
  },
  async load(id) {
    const response = await fetch(
      `/api/configurations/${encodeURIComponent(id)}`,
    );
    if (!response.ok) throw new Error("Configuration is unavailable");
    return response.json();
  },
};
```

Pass `storage` and normally `autoSync: false` to the hook. Then
`await sharing.createShareUrl()` saves a detached snapshot and returns
`#viewId=...`; `restoreFromUrl()` loads that ID through the adapter. The endpoint
above is an application example, not a service supplied by this SDK. Implement
access, retention and asset hosting in your application. A recipient needs the
same storage adapter. Storage failures reject the operation; newer incoming
links supersede older pending requests.

`getShareUrl()` and `syncUrl()` always use inline JSON. Inline URLs are limited
to 65,536 characters by default; `maxUrlLength` can change this guard, but an
application/browser/link-sharing service may impose a smaller limit. JSON state
is limited to 5 MiB, including when loaded from storage. Autosync reports errors
through `onError` and never overwrites an incoming link while restoration waits
for configuration, models or bindings.

## Parameters

| Name                                                | Description                                                                                                                                                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cameraState`, `setCameraState`                     | Current camera and instant restore handler from `useViewerCamera`. A failed/not-ready camera returns false and is retried later.                                                                              |
| `objectBindings`, `onObjectBindingsChange`          | Current active-model bindings and their setter. Complete snapshots replace the binding map.                                                                                                                   |
| `selectedObjectBinding`, `setSelectedObjectBinding` | Current selection and setter. Also pass `selectedObject` to the viewer.                                                                                                                                       |
| `configuration`, `onConfigurationChange`            | Optional `ViewerConfiguration` and replacement setter. The callback is required when restoring a snapshot that includes configuration.                                                                        |
| `isReady`                                           | Defaults to true; pass false while restored assets load.                                                                                                                                                      |
| `mode`                                              | `"configuration"` captures full bindings and supplied configuration. This is the default when `configuration` is supplied; otherwise the default is compact `"view"` mode (camera, hidden IDs and selection). |
| `storage`                                           | Optional `ViewerStateStorage` for async short links.                                                                                                                                                          |
| `maxUrlLength`                                      | Maximum inline URL length; default 65536.                                                                                                                                                                     |
| `onError`                                           | Background errors; direct API calls reject/throw to their caller. Without a handler, background errors are logged.                                                                                            |
| `paramKey`                                          | Default `"view"`; stored-link IDs use `viewId` (or `${paramKey}Id`). Other hash parameters are preserved.                                                                                                     |
| `debounceMs`                                        | Autosync debounce; default 400 milliseconds.                                                                                                                                                                  |
| `autoSync`                                          | Default true. Starts after an initial URL read/full restore; false leaves sharing explicit.                                                                                                                   |

## Returns

| Name             | Signature                              | Behavior                                                                             |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| `getState`       | `() => ShareableViewerState`           | Returns a detached version-1 snapshot.                                               |
| `restoreState`   | `(input: unknown) => Promise<boolean>` | Validates/restores JSON or parsed state; false while pending. No address-bar change. |
| `getShareUrl`    | `() => string`                         | Builds an inline link without changing the page URL.                                 |
| `createShareUrl` | `() => Promise<string>`                | Uses storage when supplied, otherwise inline JSON.                                   |
| `syncUrl`        | `() => void`                           | Writes an inline link with `history.replaceState`.                                   |
| `restoreFromUrl` | `() => Promise<boolean>`               | Restores a new link; repeated ready callbacks do not reapply the same snapshot.      |

## Compatibility and assets

- Unversioned links containing camera, hidden IDs and selection still work,
  including automatic bindings that become available after the model loads.
- For compact links that omit materials and metadata, use `mode: "view"`.
  Configuration mode includes all binding data. Existing callers that omit
  both `configuration` and `mode` keep compact links. To save full bindings
  without model/scene props, explicitly pass `mode: "configuration"`.
- Relative model, texture, annotation-image/link and environment paths become
  absolute against the sender's page URL. HTTP(S) assets and embedded image
  data URLs are supported. Original model files are not bundled.
- Blob URLs are local to a browser session and cannot make portable saves.
  Upload those assets to durable URLs before sharing, using e.g.
  `onTextureUpload`. A snapshot with blob asset references fails with a useful
  field-level error instead of generating a broken link.
- Save original assets for animations. A configuration describes the viewer's
  data; it is not a GLB export, an asset archive, or a license grant.
- Invalid JSON, unsupported versions, invalid core state shapes, unsafe object
  keys, cycles/non-JSON values and excessive state size are rejected before
  application state is changed. Application-specific metadata is preserved as
  JSON; these checks are not a substitute for validation/access control in a
  storage service.
