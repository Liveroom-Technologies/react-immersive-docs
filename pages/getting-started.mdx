# Getting Started

This guide targets **5.2.0** and **React 19**. For a complete first-render app,
start with [Vite + React](https://react-immersive.liveroom.dev/docs/frameworks/vite) or [Next.js App Router](https://react-immersive.liveroom.dev/docs/frameworks/nextjs).
For a compact API/task map, see the [AI Agent Guide](https://react-immersive.liveroom.dev/docs/agent-guide).

## Import Styles

Import the stylesheet for each component you use, once, from your application
root. In a Next.js App Router project, put these in `app/layout.tsx`:

```tsx
import "@liveroom-tech/react-immersive/styles.css"; // ModelViewer
import "@liveroom-tech/react-immersive/simple-model-viewer.css"; // SimpleModelViewer
import "@liveroom-tech/react-immersive/binding-builder.css"; // BindingBuilder
```

`SimpleModelViewer` and `BindingBuilder` are imported from their own entry
points, `@liveroom-tech/react-immersive/simple-model-viewer` and
`@liveroom-tech/react-immersive/binding-builder`, so an app downloads only the
components it uses.

If a component's stylesheet is missing, it renders unstyled, and in
development it logs a console warning naming the import to add.

## Get a License Key

`ModelViewer` and `BindingBuilder` require a `licenseKey`. (`SimpleModelViewer` needs no key, including in production; see [Licensing](https://react-immersive.liveroom.dev/docs/licensing).) To get one:

1. Sign in (or sign up) at the [React Immersive Console](https://react-immersive.liveroom.dev/console)
2. Choose a plan
3. Generate a license key from your dashboard

<Callout type="info">
  Keep keys out of public repositories. `NEXT_PUBLIC_LICENSE_KEY` (Next.js)
  and `VITE_LICENSE_KEY` (Vite) are browser-visible values, not server secrets.
  Use a key for the registered domain and follow the [licensing guide](https://react-immersive.liveroom.dev/docs/licensing).
</Callout>

## Quick Start

This example is a Next.js client component. Import `styles.css` in your root
layout, put the asset at `public/model.glb`, and set `NEXT_PUBLIC_LICENSE_KEY`
in an uncommitted `.env.local`. In Vite, import CSS in `src/main.tsx` and use
`import.meta.env.VITE_LICENSE_KEY` instead. Restart the dev server after setting
the variable. For a first render without a runtime key prop, use the
[SimpleModelViewer starter](https://react-immersive.liveroom.dev/docs/frameworks/vite).

To see your model working before you write any bindings, let the viewer
generate them:

```tsx
"use client";

import { ModelViewer } from "@liveroom-tech/react-immersive";

export default function App() {
  return (
    <div style={{ height: "100vh", overflow: "hidden" }}>
      <ModelViewer
        modelUrl="/model.glb"
        licenseKey={process.env.NEXT_PUBLIC_LICENSE_KEY!}
      />
    </div>
  );
}
```

Every mesh can then be hovered and selected, with Change Color, Change
Material, and Toggle Visibility in the side panel (or light controls for meshes
whose names contain "light"). See
[generating bindings automatically](https://react-immersive.liveroom.dev/docs/reference/model-viewer#generating-bindings-automatically)
to keep and refine them. The steps below write the bindings yourself, which
gives you control over labels, actions, metadata, and camera views.

<Steps>

### Define your object bindings

Create `objectBindings.ts` with the named export below. This sample targets the
wall node in `red_room.glb`. For another asset, discover its identifiers with
`onObjectCatalog` or BindingBuilder instead of copying the sample node name.

Each key in `objectBindings` must match a model node identifier. Unique nodes
use their authored name; duplicate names receive identifiers such as `Cube [1]`
and `Cube [2]`. BindingBuilder generates the correct identifiers automatically.
You can write the bindings by hand, or generate starter bindings in
[`BindingBuilder`](https://react-immersive.liveroom.dev/docs/reference/binding-builder) and export them as
`objectBindings.json` or a TypeScript file to import into your app.
For a configured scene, export `sceneConfig.ts` from BindingBuilder's **Scene**
tab and pass its named `sceneConfig` export to `ModelViewer` as well. The
[`BindingBuilder export and import guide`](https://react-immersive.liveroom.dev/docs/reference/binding-builder#exporting-and-reusing-files)
explains where each toolbar action lives and when to choose JSON versus
TypeScript.
If you want a ready-to-run starter, download the sample
[`red_room.glb`](https://react-immersive.liveroom.dev/red_room.glb) model and
[`objectBindings.ts`](https://react-immersive.liveroom.dev/objectBindings.ts) bindings file from these docs. Put
`red_room.glb` in your app's `public/` folder, and place `objectBindings.ts`
in your source tree so you can import it into your viewer page.

```ts filename="objectBindings.ts"
import { defineObjectBindings } from "@liveroom-tech/react-immersive/utils";

export const objectBindings = defineObjectBindings({
  Quarto_Wall_0: {
    id: "brick-wall",
    modelObjectId: "Quarto_Wall_0",
    type: "wall",
    label: "Room Walls",
    selectable: true,
    hoverable: true,
    visible: true,
    style: {},
    metrics: {},
    metadata: {},
    cameraState: {
      position: [-0.91, 0.87, 0.42],
      target: [0.09, 0.98, 0.036],
      fov: 45,
    },
    actions: [
      { id: "change-color", label: "Change Color", type: "command" },
      { id: "change-material", label: "Change Material", type: "command" },
      { id: "toggle-visibility", label: "Toggle Visibility", type: "command" },
    ],
  },
});
```

### Mount the viewer

Wrap `ModelViewer` in a full-height container. The component owns its own layout.
`defineObjectBindings` preserves literal IDs; widen mutable state to
`Record<string, ObjectBinding>` so the viewer can return an updated record.
Replace the placeholder key below with the framework-specific environment value.

```tsx filename="Viewer.tsx"
"use client";

import { useState } from "react";
import { ModelViewer, type ObjectBinding } from "@liveroom-tech/react-immersive";
import { objectBindings as initialBindings } from "./objectBindings";

export default function App() {
  const [objectBindings, setObjectBindings] = useState<Record<string, ObjectBinding>>(initialBindings);

  return (
    <div style={{ height: "100vh", overflow: "hidden" }}>
      <ModelViewer
        modelUrl="/red_room.glb"
        licenseKey="your-license-key"
        objectBindings={objectBindings}
        onObjectBindingsChange={setObjectBindings}
      />
    </div>
  );
}
```

### Control the viewer from your app

`useViewer` connects every viewer hook to `ModelViewer` at once. Spread its
`props` onto the viewer, then drive bindings, camera, selection, animations,
and scene settings from your own UI.

```tsx filename="ControlledViewer.tsx"
"use client";

import { ModelViewer, useViewer } from "@liveroom-tech/react-immersive";
import { objectBindings } from "./objectBindings";

export default function Example() {
  const viewer = useViewer({
    bindings: objectBindings,
    onAction: (event) => console.log(event),
  });
  const { toggleObjectVisibility } = viewer.bindings;
  const { resetView, focusObject } = viewer.camera;
  const { clips, play } = viewer.animations;

  return (
    <div style={{ height: "100vh", overflow: "hidden" }}>
      <ModelViewer
        modelUrl="/red_room.glb"
        licenseKey="your-license-key"
        {...viewer.props}
      />

      <button onClick={() => toggleObjectVisibility("Quarto_Wall_0")}>
        Toggle Visibility
      </button>
      <button onClick={() => resetView()}>Reset Camera</button>
      <button onClick={() => focusObject("Quarto_Wall_0")}>
        Focus Object
      </button>
      {clips.map((name) => (
        <button key={name} onClick={() => play(name)}>
          {name}
        </button>
      ))}
    </div>
  );
}
```

Leave out `bindings` and `useViewer` generates them from the model, like
`objectBindings="auto"`. See [`useViewer`](https://react-immersive.liveroom.dev/docs/hooks/use-viewer) for
everything it returns, and the other [hooks](https://react-immersive.liveroom.dev/docs/hooks/use-viewer-selection)
for wiring individual pieces yourself.

</Steps>
